## 二、建议阅读顺序

**想快速了解这个项目**：直接看 **00 号项目简报**，一页看完做什么、做到哪一步了、效果如何。

**第一次接触这个项目**：根目录 `README.md`（怎么用）→ 01（做什么）→ 02（怎么做的）→ 06（接下来做什么）。

**要改代码**：06（工作循环和铁律）→ 02（改哪个模块）→ 07（改完怎么验）。

**要动知识库**：04（数据规范）→ 05（回答规则）→ 07（跑评测）。

**它坏掉了**：08（运维手册）→ 07（测试）。

## 三、工作说明（这些约定必须遵守）

### 1. 文档和代码冲突时，以代码为准，但必须马上改文档

规范写错了要立刻修正，不能让文档变成"过期的假象"。改文档也要记 devlog。

### 2. 改行为之前先改这里

想改"回答的格式""⚠️ 的判定规则""拒答的阈值"这类东西，
**先在对应文档里写清楚改成什么、为什么改**，再去改代码。

### 3. 一次只推进一步

步骤定义在 06 号文档里，**一次只做一步，做完停下来给人看**。
不要攒着好几步一起做，出问题无法定位。

### 4. 没有指标的改动不算完成

任何涉及检索或回答的改动，都要跑 `tests/run_eval.py` 并满足 07 号文档里的红线。

### 5. 涉及数据的改动必须先备份

只要碰到 `data/app.db` 里的已有数据，先复制一份再动手。

## 四、和 devlog 的分工

| | docs/ | devlog/ |
|---|---|---|
| 记什么 | **结论**：项目应该是什么样 | **过程**：某天做了什么、为什么 |
| 变化频率 | 低，改了就是规范变了 | 高，每天都有 |
| 举例 | "拒答阈值默认 0.40" | "今天把阈值从 0.35 调到 0.40，因为噪声最高 0.297 而真实问题最低 0.627" |

## 五、常用命令速查

```bat
rem 启动服务（会自动建当天开发日志）
启动助手.bat

rem 跑评测（改完代码必跑）
.venv\Scripts\python.exe tests\run_eval.py

rem 跑评测（连大模型一起，慢但真实）
.venv\Scripts\python.exe tests\run_eval.py --llm

rem 记录开发日志
.venv\Scripts\python.exe tools\devlog.py done "完成了什么"
.venv\Scripts\python.exe tools\devlog.py todo "下次做什么"
.venv\Scripts\python.exe tools\devlog.py show

rem 重建检索索引（改了条款或分词词典后）
.venv\Scripts\python.exe tools\build_index.py

rem 导入自己的资料
.venv\Scripts\python.exe tools\import_doc.py "D:\资料\某标准.pdf"
```
