## 一、日常操作

| 想做什么 | 怎么做 |
|---|---|
| 启动 | 双击 `启动助手.bat`，浏览器会自动打开 |
| 停止 | 关掉那个黑色窗口，或双击 `停用助手.bat` |
| 确认在跑 | 浏览器打开 <http://127.0.0.1:8765>，右上角显示"本地模型已就绪" |
| 一键体检 | `.venv\Scripts\python.exe tools\health_check.py`（服务在跑时用） |
| 备份数据 | 复制 `data\app.db` 一个文件就够 |
| 换电脑 | 把整个文件夹拷过去，双击 `启动助手.bat` |
| 升级后补配置 | `.venv\Scripts\python.exe tools\sync_config.py`（补 `.env` 里缺的新配置项，不会覆盖你改过的值） |

服务已经在跑的时候再双击 `启动助手.bat`，**不会报错**，只会打开浏览器。

## 二、几个关键路径

| 路径 | 是什么 | 能删吗 |
|---|---|---|
| `data\app.db` | **知识库 + 全部聊天记录**。唯一需要备份的文件 | ❌ 删了就全没了 |
| `data\seed\` | 种子条款数据（283 条） | ❌ 删了要重新收集 |
| `data\logs\app.log` | **运行日志**，按天切分保留 14 天。出问题先看这里 | ✅ 删了会重建 |
| `data\backups\` | **数据库自动备份**，保留最近 20 份。导入资料和撤销导入前都会自动生成 | ⚠️ 建议留着，这是最后的退路 |
| `data\models\` | 中文语义模型缓存（约 100MB） | ✅ 删了会自动重下 |
| `data\models\import\` | `tools\fetch_model.py` 下载的 GGUF 原始文件（注册进 Ollama 后可以删） | ✅ 注册完就能删 |
| **Ollama 的模型目录** | 大模型文件（约 9GB）。位置由用户级环境变量 `OLLAMA_MODELS` 决定，本项目把它设成了 `D:\ollama-models` 以免占用 C 盘 | ❌ 删了要重新下载 |
| `.env` | 你的配置 | ⚠️ 删了会用默认值重新生成 |
| `devlog\` | 开发日志 | ✅ 纯记录，删了不影响功能 |
| `tests\eval_report.md` | 最近一次评测报告（**不进版本库**，所以全新 clone 里没有，跑一次评测就有了） | ✅ 每次跑评测会重新生成 |

## 三、常见故障速查

### 症状：双击 `启动助手.bat` 完全没反应

**先看有没有黑窗口弹出。** 三种情况分别是：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 窗口一闪就消失 | 脚本执行中途出错 | 按下面「手动运行看报错」处理 |
| 完全没有任何窗口 | 杀毒软件拦截了 .bat | 把项目文件夹加进杀毒软件白名单 |
| 窗口开着但浏览器没开 | 服务已在运行，或浏览器没响应 | 手动打开 <http://127.0.0.1:8765> |

**手动运行看报错**（这样窗口不会自动关）：

```bat
cd /d <项目所在目录>
启动助手.bat
```

**最常见的两个原因**：
1. 没装 Python，或装的时候没勾选 "Add python.exe to PATH"
2. 服务其实已经在跑了（双击不会重复启动，只会打开浏览器）

> ⚠️ **维护者注意（踩坑定的规则，不要放宽）**：
> `启动助手.bat` 和 `停用助手.bat` **必须保持纯英文 ASCII，一个字中文都不能写**。
>
> cmd.exe 按当前控制台代码页逐字节读批处理文件。文件里有中文而代码页不匹配时，
> 命令会被撕碎——实测 `echo [1/4] 运行环境已就绪` 被解析成
> `'运行环境已就绪' is not recognized`，甚至 `echo` 被拆成 `ho`。
> **现象就是双击后什么都不发生**，非技术用户完全无从下手。
>
> 试过但行不通的两个方案：
> - UTF-8 + `chcp 65001`：cmd 按当前代码页读文件，读到 `chcp` 那行之后仍然错位
> - 存成 GBK：只在控制台代码页正好是 936 时正常，换环境（如 65001）一样崩
>
> **正确做法：中文提示一律交给 Python 输出**。Python 3.6+ 在 Windows 上通过
> 宽字符 API 写控制台，不受代码页影响——这正是 `tools/first_run.py` 和
> `tools/stop_service.py` 存在的原因。
>
> 这条规则已加进 `tests/check_syntax.py`，改完跑一次静态检查就会被拦下。
> 完整说明见 `tools/fix_bat_encoding.py` 头部注释。

### 症状：双击 bat 窗口一闪就没了（补充排查）

**原因**：出错了，但窗口关得太快看不到信息。

**怎么办**：
1. 按 `Win + R`，输入 `cmd`，回车
2. 把 `启动助手.bat` 拖进那个黑窗口，回车
3. 现在能看到完整的错误信息了

**最常见的原因**：没装 Python，或装的时候没勾选 "Add python.exe to PATH"。

---

### 症状：右上角一直显示"Ollama 未运行"或"缺少大模型"

**逐项检查**：

1. **Ollama 装了吗**：开始菜单里能找到「Ollama」吗？没有就去 <https://ollama.com/download> 下载安装。

2. **Ollama 在跑吗**：任务栏右下角（可能藏在 `^` 里）有羊驼图标吗？
   没有就点开始菜单里的 Ollama 打开它，等十几秒再刷新页面。

3. **模型下了吗**：打开 cmd 执行 `ollama list`。
   列表里没有 `qwen2.5:7b-instruct` 就执行：
   ```
   ollama pull qwen2.5:7b-instruct
   ```
   **如果下载巨慢或卡在 99% 不动**（国内很常见），改用高速方案：
   ```
   cd /d <项目所在目录>
   .venv\Scripts\python.exe tools\fetch_model.py
   .venv\Scripts\python.exe tools\register_model.py
   ```
   实测 41 MB/s，两分钟下完。

4. **模型名字对得上吗**：`ollama list` 里的名字必须和 `.env` 里 `LLM_MODEL=` 完全一致。

> **没模型也能用**：会自动降级为"只检索条款"，照样给条款编号和原文。

### 症状：回答很慢

| 情况 | 说明 |
|---|---|
| 第一次提问慢 | 正常，模型首次加载要 2-3 秒 |
| 一直很慢（>15秒） | 可能是显存不够，模型跑到内存里了。检查 `nvidia-smi` 看显存占用 |
| 想更快 | 换小模型：`.env` 里改成 `qwen2.5:3b-instruct`，然后 `ollama pull qwen2.5:3b-instruct` |

实测参考：RTX 5070 12GB 跑 7B 模型，生成速度约 87 token/秒，单次回答 1.3-4.3 秒。

---

### 症状：说"知识库中未找到"，但这明明是个合规问题

**两种可能**：

1. **确实不在覆盖范围内**。当前只有等保2.0 安全通用要求 / NIST CSF 2.0 / OWASP Top 10 2021。
   问《个人信息保护法》具体条文就找不到（知识库里只有等保的个人信息保护条款）。

2. **描述太笼统**，检索分数低于阈值 0.40。补充细节再问：
   系统是否连外网、存了哪些数据、有多少人用、自建还是买云服务。

**如果是正常问题却被拒答**（假拒答），调低阈值：
打开 `.env`，把 `RETRIEVAL_MIN_SCORE=0.40` 改成 `0.35`，重启服务。

**如果无关问题也被答了**（假命中），调高到 `0.45`。

> 改完阈值记得跑一次 `tests\run_eval.py` 确认拒答率还是 5/5。

### 症状：界面显示乱码

**正常情况下不会发生。** 如果发生了：

1. 按 `F5` 刷新页面（大概率是页面没加载完）
2. 检查 `.env` 文件是不是被存成了 GBK 编码——必须用 **UTF-8** 保存

### 症状：端口 8765 被别的程序占了

改 `.env`：

```
APP_PORT=8766
```

重启服务，然后访问 <http://127.0.0.1:8766>。

**查看谁占了端口**：
```bat
netstat -ano | findstr :8765
```
最后一列是进程号，用任务管理器按 PID 找。

### 症状：知识库页条款数是 0

**原因**：种子数据没导入成功。

**怎么办**：
1. 检查 `data\seed\` 下有没有 3 个 json 文件
2. 手动触发导入：
   ```
   cd /d <项目所在目录>
   .venv\Scripts\python.exe -c "from app import db, ingest; db.init_db(); print(ingest.ensure_seed_loaded())"
   ```
3. 如果报 JSON 格式错误，那个文件被改坏了，需要恢复

### 症状：搜索搜不到明显的条款

**原因**：索引和条款对不上（改了条款但没重建索引）。

**怎么办**：
```
cd /d <项目所在目录>
.venv\Scripts\python.exe tools\build_index.py
```

## 四、配置速查（`.env`）

用记事本打开 `.env`，改完**必须重启服务**。

| 配置项 | 默认值 | 什么时候改 |
|---|---|---|
| `APP_PORT` | `8765` | 端口被占用时 |
| `APP_AUTO_OPEN` | `true` | 不想自动开浏览器就改 `false` |
| `LLM_MODEL` | `qwen2.5:7b-instruct` | 换模型时（要和 `ollama list` 一致） |
| `LLM_TIMEOUT` | `180` | 模型特别慢时调到 `300` |
| `HYBRID_KEYWORD_WEIGHT` | `0.5` | 想更依赖关键词就调高（两项之和为 1.0） |
| `HYBRID_VECTOR_WEIGHT` | `0.5` | 想更依赖语义就调高 |
| `RETRIEVAL_MIN_SCORE` | `0.40` | 假拒答调低，假命中调高 |
| `RETRIEVAL_TOP_K` | `6` | 送给模型的条款条数，调大更全面但更慢 |
| `ENABLE_VECTOR_SEARCH` | `true` | 设 `false` 则只用关键词（零下载） |
| `SAVE_HISTORY` | `true` | 不想存聊天记录就改 `false` |

## 七、出问题时应该收集什么信息

如果找我排查，**先跑一键体检**，把输出整个发过来：

```bat
cd /d <项目所在目录>
.venv\Scripts\python.exe tools\health_check.py
```

它会一次打印：服务状态、大模型状态、语义检索、质量自检结果、知识库规模与来源分布、关键配置。

如果体检本身都跑不起来，再补上这几条：

```bat
rem 最近的错误日志（最关键）
powershell -Command "Get-Content data\logs\app.log -Tail 40"

rem 模型列表
ollama list

rem 端口占用
netstat -ano | findstr :8765
```

另外说明一下：**页面上问了什么、回答得不对** 这类问题，用这个命令看细节：

```bat
.venv\Scripts\python.exe tools\inspect_last_answer.py
```

它会打印最近一次回答的引用条款、⚠️ 判定依据和完整内容。

## 八、日志怎么用（P1-1 新增）

日志在 `data\logs\app.log`，按天切分，保留 14 天。

**看最近发生了什么**：
```bat
powershell -Command "Get-Content data\logs\app.log -Tail 30"
```

**找某次提问**：
```bat
findstr "问答" data\logs\app.log
```

**找错误**：
```bat
findstr "ERROR WARNING" data\logs\app.log
```

日志里几类关键行：

| 关键字 | 含义 |
|---|---|
| `启动完成 · 知识库 N 条` | 每次启动的记录 |
| `问答 耗时=x 模式=y 命中=z 引用=N ⚠️=M` | 每次提问的摘要 |
| `引用异常 \| 已剔除不在本次检索结果中的条款编号` | **模型开始编条款号了**，值得警惕 |
| `大模型不可用，降级为条款检索` | Ollama 没起来 |
| `接口未捕获异常` | 有 bug，后面跟完整堆栈 |
| `质量自检未通过` | 检索指标跌破红线 |

## 九、数据备份与恢复（P2-2 新增）

### 自动备份

以下时机系统会**自动**备份 `data/app.db` 到 `data/backups/`：

- 每次导入资料之前（备份失败会中止导入，绝不"没备份就动手"）
- 每次撤销导入之前（所以撤销本身也可撤销）

保留最近 20 份，更旧的自动删除。

### 手动备份

直接复制 `data\app.db` 一个文件即可。

### 撤销一次导入

知识库页 → 「查看导入批次」→ 找到最近一次「用户导入」→ 点「撤销这次导入」。

**限制**（都是有意的，不是 bug）：
- 只能撤销**用户自己导入**的批次。内置种子是基线，撤了知识库就空了
- 只能撤销**最近一次**。恢复备份会把之后的改动一起退掉
- 撤销前系统会再备份一次当前状态

### 最坏情况：手工恢复

如果服务起不来，但想手动把数据库退回到某个备份：

```bat
rem 1. 先停掉服务（双击 停用助手.bat）
rem 2. 用备份覆盖（把文件名换成 data\backups 里实际的那个）
copy data\backups\app_20260928_224025_before_import.db data\app.db

rem 3. 重新启动
启动助手.bat
```

覆盖前建议先把当前的 `app.db` 另存一份，别把现有的也弄丢了。
