# 03 · 界面设计规范

> 面向**不懂技术的用户**。所有设计决定都要回答一个问题：
> "一个 50 岁、不太会用软件的老板，能不能一眼看懂？"

---

## 一、设计原则

| 原则 | 具体做法 | 反面例子 |
|---|---|---|
| **一眼看懂** | 字号偏大、留白充足、不用图标代替文字 | 只有 ⚙️ 图标没有"设置"二字 |
| **敢用大白话** | 界面上不出现"检索""向量""召回"这类词 | 显示"召回 6 条条款" |
| **风险要跳出来** | 琥珀色块 + 左侧粗边条 + 三角图标，视觉上必须先看到 | 把风险混在正文里 |
| **专业感来自克制** | 中性灰打底 + 单一品牌蓝 + 单一警示琥珀，细边框 + 极轻阴影 | 彩虹色、大圆角、重阴影、彩色渐变 |
| **断网也要好看** | 零外部 CDN，字体自己托管在 `web/fonts/` | 引用 Google Fonts / 在线图标库 |
| **留白是设计的一部分** | 内容有最大宽度、左右留白充足，不是所有东西都垂直堆叠居中 | 每一屏都把元素居中堆成一列 |

> **2026-10-08 改版说明**：这一版按"资深 UI/UX 设计师"的需求书整体重构过。
> 之前的问题是"什么都蓝、什么都大圆角、什么都居中、拿 emoji 当图标"——
> 也就是一眼能认出来的模板感。改版的方向是**把颜色收掉、把间距立起来、把图标统一**。

---

## 二、设计变量（改配色只改这里）

定义在 `web/css/style.css` 最上面的 `:root`。**规则：颜色只从变量里取，不许在别处写十六进制。**

### 2.1 中性色阶（全站底色、边框、文字的唯一来源）

| 变量 | 值 | 用途 |
|---|---|---|
| `--n-0` ~ `--n-900` | `#ffffff` → `#14171a` 共 12 级 | 所有灰 |
| `--bg` | `--n-50`（`#f8f9fa`） | 页面底 |
| `--bg-subtle` | `--n-25` | 侧栏等次级面 |
| `--surface` | `--n-0` | 卡片面 |
| `--border` / `--border-strong` | `--n-200` / `--n-300` | 常规描边 / 输入框描边 |
| `--text` | `--n-800` | 正文（对比度约 13:1） |
| `--text-2` | `--n-600` | 次要文字（约 8:1） |
| `--text-3` | `#5f6873` | 三级文字（约 5.6:1） |
| `--text-faint` | `--n-400` | **只许用于图标和占位符**（约 3.3:1，不承载信息） |

### 2.2 唯二的彩色

| 变量 | 值 | 用途 |
|---|---|---|
| `--accent` | `#2563eb` | 品牌蓝。主按钮、链接、当前选中 |
| `--accent-hover` | `#1d4ed8` | 悬停 |
| `--accent-soft` / `--accent-border` / `--accent-text` | `#eff6ff` / `#bfdbfe` / `#1e40af` | 淡底、淡描边、淡底上的文字 |
| `--accent-ring` | `rgba(37,99,235,.18)` | 焦点环 |
| `--warn-bg` / `--warn-border` / `--warn-text` / `--warn-soft` | `#fffbeb` / `#fcd34d` / `#92400e` / `#fef3c7` | ⚠️ 风险（**只服务于"风险"这一个语义，不做装饰**） |
| `--danger*` | `#b91c1c` / `#fef2f2` / `#fecaca` | 失败、删除 |
| `--ok*` | `#15803d` / `#f0fdf4` / `#bbf7d0` | 成功、已收录 |

**为什么淡蓝色变成了 `#2563eb` 这种偏深的蓝**：用户要的是"淡蓝主色"，
但之前把淡蓝刷满了整屏（底色、边框、阴影、顶栏渐变全是蓝），
结果既刺眼又廉价。现在**蓝色只出现在真正要引导点击的地方**，
其余全部交给中性灰——这才有"成熟产品"的感觉。

### 2.3 间距、圆角、阴影、动效

| 变量 | 值 | 说明 |
|---|---|---|
| `--sp-1` ~ `--sp-8` | `4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px` | **8pt 间距系统**。所有 margin/padding 只能取这八个值 |
| `--r-xs` ~ `--r-lg` | `4 / 6 / 8 / 10px` | 圆角整体克制，**最大 10px**（原来的 16px 大圆角是模板感来源之一） |
| `--r-full` | `999px` | 只用于圆形（头像、状态点） |
| `--sh-xs` / `--sh-sm` / `--sh-md` | 极轻 | 阴影只两档常用，重阴影是明令禁止项 |
| `--t` | `180ms cubic-bezier(.4,0,.2,1)` | 动效统一，只用于 hover / focus / 展开 |
| `--topbar-h` | `56px` | 顶栏高 |
| `--content-max` | `820px` | 聊天正文栏宽，约等于 12 列网格的 8 列 |

> 顶栏**不用渐变**了：改成 56px 白底 + 底部一条细边框 + `backdrop-filter`。
> 高饱和渐变 + 重投影是"学生作业感"最大的两个来源。

## 三、字体与排版

| 项目 | 规定 |
|---|---|
| 字体族 | `"Inter Variable", "Inter", -apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif` |
| 字体本体 | **本地托管**在 `web/fonts/`（两个 woff2 子集，共 123 KB），经 `/static/fonts/...` 提供；`@font-face` 用 `font-weight: 100 900` + `font-display: swap` |
| 中文 | **不落在 Inter 上**（Inter 不含汉字），由后面的系统字体渲染。这是取舍，不是缺陷 |
| 字号阶 | `--fs-11/12/13/14/15/16/20/24`——**只许取这几档，不许写 11.5px 这种半像素值** |
| 正文大小 | `15px`（比常规 14px 大一档，照顾年长用户） |
| 行高 | `1.6 ~ 1.72`（中文行高要松，紧凑了读着累） |
| 字重 | 标题 600~700，正文 400~500。**没有第三档** |
| 次要说明 | `--fs-12` / `--fs-13`，颜色 `--text-2` 或 `--text-3` |
| 代码/编号 | `Consolas, "Courier New", monospace`（条款编号用等宽，便于比对） |
| 最大内容宽度 | 聊天区 820px 居中；知识库正文栏 1200px；再宽中文一行太长不好读 |

**为什么宁可多下 123 KB 也不引在线字体**：这个工具承诺"断网也能用"。
引 Google Fonts 的话，断网时字体会回退，字宽变化会让整个排版抖动——
一个"绝大多数字体都来自网络"的设计，在离线场景下等于没有设计。
两个子集（latin + latin-ext）都留下，是为了导入文档里出现带变音符的拉丁字符时
不会跟正文拆成两种字体混排。

## 三点五、图标规范（2026-10-08 新增）

**全站不使用 emoji 当图标。** 一律用内联 SVG 雪碧图。

| 项目 | 规定 |
|---|---|
| 定义位置 | 每个页面 `<body>` 顶部一个隐藏的 `<svg width="0" height="0">`，里面是若干 `<symbol id="i-xxx" viewBox="0 0 24 24">` |
| 用法 | `<svg class="i" viewBox="0 0 24 24" aria-hidden="true"><use href="#i-shield"/></svg>` |
| 样式 | `.i { width: 1em; height: 1em; fill: none; stroke: currentColor; stroke-width: 1.75; stroke-linecap: round; stroke-linejoin: round; vertical-align: -0.125em; }` |
| 颜色 | 跟着 `currentColor` 走，**不给图标单独写颜色**（例外：`.i-warn` 是琥珀色，表示风险） |
| 无障碍 | 一律加 `aria-hidden="true"`——图标旁边的文字已经说清楚了，重复朗读反而吵 |
| 在 JS 里用 | `web/js/api.js` 的 `ICON(name, cls)` 生成上面那段 SVG |
| 校验 | `tests/check_syntax.py` 的 `check_svg_icons()` 会核对每个被引用的图标名是否真有定义 |

**为什么必须校验**：图标名写错时浏览器**不报任何错**，只是画一片空白，
肉眼很容易漏过去。这类"静默失败"必须靠静态检查兜住。

**两个已知例外（原生控件画不了 SVG）**：

- 原生 `<select>` 里只能放纯文字，所以筛选下拉写的是「数据加密」而不是「⚠️ 数据加密」；
- 系统原生 `alert()` 弹窗同样只能留文字符号。

这两处不算违反规范，是浏览器能力边界。

## 四、核心组件

### 4.1 消息气泡

| 角色 | 样式 |
|---|---|
| 用户 | 右侧，`--accent-soft` 淡蓝底 + `--accent-border` 描边，圆角 `10px 10px 4px 10px`（右下角收一个口，暗示"我说的话"） |
| 助手 | 左侧，**不加卡片边框**——靠排版本身承担层级。头像是一个 26px 圆形衬底 + `i-shield` 线性盾牌图标 |

> 旧版是"用户蓝底白字 + 助手白底描边"，再加上蓝色顶栏，蓝色出现了五次以上。
> 现在助手侧完全去卡片化，视觉重量靠字号和留白拉开。

### 4.2 ⚠️ 风险条（必须最醒目）

- 位置：**答案正文之上**，用户第一眼看到
- 底色 `--warn-bg`，左侧 4px 粗边 `--warn-border`，圆角 `--r-md`
- 标题：三角图标 + `高风险项提示（建议重点关注）`，字重 700
- 每条风险写两行：`三角图标 + 风险名` + 一句"为什么算高风险"
- 风险名后面可以跟一句小字的条款号提示（`.risk-clauses`，琥珀色 `--warn-text`）
- 数量控制：**最多 3 条**（只有三类高风险），而且要精准，不能凑数

### 4.3 引用卡片

- 默认**折叠**，只显示：展开箭头（`i-chevron-right`，展开时旋转 90°）+ 条款编号 + 标准名 + 标题
- 点击展开后显示：章节路径 › 正文 › 标签
- 高风险条款的卡片左侧边条变黄
- **等保条款必须带"要点摘要（非标准原文）"灰色标记**——这是版权和诚信要求
- 编号用等宽字体 + 白底描边，视觉上像"凭证"，强化可信感

### 4.4 追问区块

- 只在"信息不足"时出现（`need_clarification = true`）
- 蓝底浅色块，标题："为了给出更准确的条款依据，请补充以下信息："
- 每个问题是一个可点击按钮，点了自动填进输入框（降低打字负担）
- **不需要追问时绝对不能显示**——否则用户会以为必须回答

### 4.5 状态标记（mode badge）

| 场景 | 文案 | 颜色 |
|---|---|---|
| 信息不足 | 信息不足，需要您补充几个情况 | 蓝 |
| 提到的对象未收录 | 您提到的 X 未收录，以下是与它相关的合规要求 | 琥珀 |
| 大模型不可用 | 大模型不可用，已降级为条款检索 | 橙 |
| 知识库没找到 | 知识库中未找到对应条款 | 红 |

**优先级：需要先了解情况 > 未收录 > 追问 > 降级 > 未找到。**
需要追问时绝不能显示成"没找到"。

### 4.6 快捷问题卡

- 8 个，`grid-template-columns: repeat(auto-fill, minmax(232px, 1fr))` 自适应
- 每张卡：一个 16px 线性图标 + 一句标题 + 一句口语化的问题示例
- 悬停时边框变深，**不做上浮位移**（位移会让整块区域"抖"，是廉价感的来源）
- 卡片是 `role="button"` + `tabindex="0"`，Enter 和空格都能触发——**键盘用户也要能点**

## 五、文案规范

界面上的**每一个字**都要按这个标准写。

### 5.1 用大白话，不用技术词

| ❌ 不要写 | ✅ 改成 |
|---|---|
| 检索到 6 条条款 | 找到 6 条相关条款 |
| 向量检索已启用 | 智能匹配已开启 |
| 降级为 retrieval_only 模式 | 大模型暂时用不了，先帮您列出相关条款 |
| 模型推理超时 | 电脑算得有点慢，请再试一次 |
| JSON 解析失败 | 回答格式有问题，已按原文显示 |

### 5.2 出错时要说"下一步怎么办"

```
❌ 连不上 Ollama
✅ 连不上本地大模型服务。
   请确认 Ollama 正在运行（任务栏右下角应该有羊驼图标），
   或者在开始菜单里打开 Ollama 再试一次。
```

### 5.3 术语第一次出现必须解释

| 术语 | 必须跟一句解释 |
|---|---|
| 身份鉴别 | 身份鉴别（也就是确认"你是你"，比如账号密码） |
| 最小权限 | 最小权限（只给干活必需的权限，不多给） |
| 个人信息 | 个人信息（手机号、身份证号、住址这些能认出具体人的信息） |

### 5.4 不用 Markdown 标题符

前端不渲染 Markdown。回答里只用 `1. 2. 3.` 和 `-`，
代码里已有 `strip_markdown_headings()` 清理模型输出的 `#`。

## 六、交互反馈

| 场景 | 反馈 |
|---|---|
| 正在检索 | 三个跳动小圆点 + "正在检索知识库条款…" |
| 正在生成 | 小圆点 + "已命中条款（最高匹配 8.1.4.1 身份鉴别），正在生成回答…" |
| 复制成功 | 底部黑色胶囊提示"已复制到剪贴板"，2.6 秒后消失 |
| 导入/重建索引 | "正在导入并重建索引，请稍候…"，持续 12 秒 |
| 启动中 | 全屏遮罩 + 进度条 + "首次启动需要导入知识库，大约半分钟" |

**所有耗时超过 1 秒的操作都必须有反馈**，否则用户会以为卡死了然后反复点击。

## 七、无障碍与容错

无障碍不是"给残疾人做的附加功能"。**键盘能不能用、对比度够不够、屏幕阅读器读不读得懂，
本质上是"这个界面有没有把话说清楚"**——对所有人都有好处。

| 要求 | 实现 |
|---|---|
| 只用颜色区分信息 | 不允许。风险块同时有三角图标和文字 |
| 对比度 | 正文 13:1、次要文字 8:1、三级文字 5.6:1；`--text-faint`（3.3:1）**只许用于图标和占位符** |
| 键盘可用 | 输入框 Enter 发送、Shift+Enter 换行；**所有可点击元素都必须是真 `<button>`**，不能是带 `onclick` 的 `span`/`div` |
| 焦点可见 | 全站 `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px }`，**不允许 `outline: none`** |
| 跳转链接 | 每页第一个可聚焦元素是 `.skip-link`（"跳到对话内容"/"跳到条款列表"），平时藏在屏幕外，聚焦时出现 |
| 屏幕阅读器专用文字 | `.sr-only`；`web/index.html` 里有一个 `<h1 class="sr-only">对话自查</h1>` 作为不会被对话挤掉的页面名 |
| 语义化标签 | `header` / `main` / `aside` / `nav`，并且**只放一个 `<h1>`，标题层级不跳级** |
| 活区播报 | `#chatScroll` 是 `role="log"`、`#statusChip` 是 `role="status"`、`#toast` 是 `role="status" aria-live="polite"` |
| 图标不重复朗读 | 所有装饰性 SVG 加 `aria-hidden="true"` |
| 减少动效 | `@media (prefers-reduced-motion: reduce)` 下把过渡压到接近 0 |
| 更高对比度 | `@media (prefers-contrast: more)` 下加深文字和描边 |
| 误删保护 | 删除对话、删除标准前必须 `confirm()` 二次确认 |
| 长文本不撑破 | 所有可能超长的元素都有 `overflow-wrap: break-word` |
| 空状态有引导 | 没有历史对话时显示"还没有历史对话"，不留空白 |

**2026-10-08 用 axe-core 扫描修掉的 5 处真实问题**（都记在 devlog 里）：

1. 历史对话列表声明了 `role="list"`，子元素却没有 `role="listitem"`；
2. 页面根本没有 `<h1>`；
3. **历史对话项是带 `onclick` 的 `span`，键盘用户聚焦不到，等于切不了对话**；
4. 知识库页 `<h3>` 直接跟在 `<h1>` 后面，跳级；
5. **目录树节点同样聚焦不到**。

第 3 和第 5 条不是"为了让扫描变绿"而改的——**自动规则报出来的是症状，底下是真缺口**。

> **一个容易误判的地方**：axe 会在滚动容器里报一堆 `color-contrast` 的
> "incomplete"（无法确定背景色）。实测这些节点的中心点全在可视区之外
> （比如 `#pager > span` 的 `rect.top=5124`），是几何裁剪造成的，
> **不是真的对比度问题，不要去"修"它**。
> `tests/test_frontend.py` 里的断言是"每个待定节点的中心点都在视口外或尺寸为 0"。

## 八、响应式

只有三个断点，不要随意加：

| 断点 | 变化 |
|---|---|
| `> 1080px` | 完整布局：左侧 264px 侧栏 + 居中正文栏 |
| `≤ 1080px` | 侧栏收窄，知识库统计卡少排一列 |
| `≤ 860px` | **变成抽屉**：侧栏/目录树改成 `position: fixed` + `transform: translateX(-100%)`；顶栏出现汉堡按钮 `#navToggle`；`body.nav-open` 时侧栏归位并显示遮罩 `#navScrim`（点遮罩、按 Escape、窗口拉宽都会自动收回） |
| `≤ 520px` | 单列；快捷卡片一行一张；统计卡两列 |

抽屉交互写在 `web/js/api.js` 的 `initShell()` 里（两个页面共用），
**不在 `chat.js` / `kb.js` 里各写一份**。

## 九、改界面时的检查清单

改完必须逐条确认：

- [ ] 127.0.0.1:8765 正常显示，**浏览器控制台无报错**
- [ ] 断网状态下样式正常（不能依赖任何 CDN）
- [ ] 窗口缩到 1000px 宽不出现横向滚动条
- [ ] 提问一次，引用卡片能展开收起
- [ ] 问一个高风险问题，⚠️ 条正常显示
- [ ] 问"今天天气"，正确显示"未找到"红色标记
- [ ] 问"我们的系统安全吗"，显示蓝色"需要补充信息"标记（**不是红色未找到**）
- [ ] 知识库页目录树、搜索、分页都正常
