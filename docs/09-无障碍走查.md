## 一、自动化部分：AX 树代理走查

不是真的屏幕阅读器，而是用 Chrome DevTools Protocol 把页面当成「读屏软件看到的视图」
去检查：浏览器为辅助技术合成的 **AX 树**（角色、可访问名称、层级、live region 属性），
加上几何坐标与焦点状态。

- 探针：`tests/a11y_walkthrough.js`（纯浏览器脚本，不访问网络、不读时间、不依赖随机数）
- 驱动：`tests/test_frontend.py` 里的用例「屏幕阅读器代理走查：阅读顺序、可访问名称、
  标题结构、live region 与流式播报」，真 Chrome + 真服务，离线可跑（不需要 Ollama）
- 失败即用例变红，不需要人看截图

### 1.1 它能自动验证什么

| 维度 | 具体断言 |
|---|---|
| 可访问名称 | 所有 `tabindex >= 0` 且可见、未禁用的控件都有非空名字（`aria-label` / `aria-labelledby` / `<label for>` / 文本内容 / `<title>` 依次兜底） |
| 阅读顺序 | 把标题区按 DOM 顺序和按「视觉坐标（先 top 后 left）」各排一遍，比对是否一致；抓「同一行左右颠倒」「上下颠倒」 |
| 标题结构 | 可见标题里**正好一个 `h1`**，且层级不跳级（`h1 > h2 > h3`） |
| live region 配置 | `#toast`、`#statusChip`、`#srAnnounce` 的属性齐全且不会静音（`role` 隐含的 polite 也算数） |
| 流式播报策略 | 往页面里注入**假 SSE**（12 个 delta + 1 次 meta），断言：生成期间 `#chatScroll` 是 `aria-live="off"` + `aria-busy="true"`；结束后恢复；`#srAnnounce` 恰好写进一句「回答已生成…」 |
| 焦点进出 | 390px 下打开抽屉后侧栏 `left=0`、`aria-expanded` 同步、焦点进入面板、`main` 带 `inert`；Escape 关闭后焦点回到触发按钮 |

### 1.2 它**不能**验证什么（所以必须真人）

- **播报内容是否可理解**：NVDA 把「回答已生成，共 412 个字，引用 3 条条款，1 条风险提示」
  读出来顺不顺耳、要不要改成更口语的说法——探针只知道文本写进去了。
- **播报时序与打断**：播报还没读完用户又按了 Enter 会怎样；`aria-busy` 的静音窗口
  在真实语速下是不是太长或太短。
- **条款编号怎么念**：`8.1.4.1` 被读成「八点一四点一」还是「八 一 四 一」，
  中文标点、`⚠️` 的替代文本是否合适。
- **真实 Tab 走一遍的手感**：探针只拿到 `tabIndex` 和坐标，不知道键盘用户会不会
  在 18 个控件里迷路。
- **其他辅助技术**：高对比度模式、放大镜、语音控制、眼动仪，均未覆盖。

## 二、流式回答的播报策略（实现约定，供走查时对照）

代码：`web/js/chat.js` 的 `announce()` 与 `send()`；DOM：`web/index.html` 的 `#srAnnounce`。

1. **生成期间静音**：`#chatScroll`（`role="log"`，隐含 polite）临时改成
   `aria-live="off"` + `aria-busy="true"`。原因很实际：前端每收到一个 delta 就整段重写
   `.answer-text`，若保持 polite，读屏会把整段回答从头重读 N 次。
2. **结束时播一句摘要**：恢复默认属性后，向 `#srAnnounce`
   （`role="status" aria-live="polite" aria-atomic="true"`）写入
   「回答已生成，共 N 个字，引用 N 条条款，N 条风险提示」。
3. **播报的是摘要，不是全文**。长答案整段播报要读几分钟，而且 delta 阶段已经视觉呈现；
   要听全文的用户可以 Tab 到回答区用读屏的「朗读全部」。
4. **出错时**播报气泡里同一句错误文案（`出错了：…` / `请求失败：…` / `没有收到回答：…`）。
5. 同一段文字连写两次读屏不会重播，所以 `announce()` 先清空再写。

|---|---|---|---|
| 1 | 打开首页，按 `NVDA+空格` 进浏览模式，读整页 | 「对话自查」页面名，随后是主区域；雪碧图、装饰图标、头像不被朗读 |  |

## 四、怎么跑自动化部分

```powershell
# 只跑前端套件（需要 Node + 本机 Chrome；会临时起服务、用临时库，不动 data/app.db）
.venv\Scripts\python.exe tests\test_frontend.py

# 单独看探针输出（调试用）
node tools\cdp_eval.js --url http://127.0.0.1:8000/ --script tests\a11y_walkthrough.js `
     --settle 2500 --out a11y.json
```

探针返回对象的字段：`focusables` / `emptyNames` / `landmarks` / `readingOrder` /
`orderMismatch` / `headings` / `live` / `streaming`（含 `snapshots.midStream`
`snapshots.after` `announcer` `mutations`）/ `problems`。

## 五、已知边界

- 只覆盖首页与知识库页的**桌面宽度 + 390px 两档**；中间宽度（520–860）没有专门的
  无障碍断言，只有「无横向溢出」。
- 探针用的是 Chromium 的 AX 树，与 NVDA 在 Firefox/Edge 上的实际表现可能有差异。
- `aria-live="off"` 静音窗口的**时长**没有断言（探针只断言属性，不断言时间）。
