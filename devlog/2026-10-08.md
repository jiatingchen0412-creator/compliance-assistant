## 问题与决策
- 14:47 【核心缺口】防幻觉只防住「检索不到」，没防住「用户点名知识库外的法规」。app/routers/chat.py:253-261 把 found 硬编码为 True（「found 由检索结果决定，不听模型的」），且 271-272 行会用 guard.strip_false_no_result() 删掉模型说的「找不到」。于是问《个人信息保护法》第13条时，检索返回等保「个人信息保护」条款（分数过阈值）→ 强制作答 → 模型凭自己记忆编造法律内容，再挂上 8.1.4.26 等引用。3/3 稳定复现，且编造内容本身是错的（第13条讲处理个人信息的法律依据，不是「合法性正当性必要性原则」）。这直接违反用户第一条硬性要求。
- 14:47 【评测盲区】tests/eval_questions.json 30 题只有 hit(25)/reject(5) 两类，而 reject 的判定标准是 app/quality.py:74 的 best >= RETRIEVAL_MIN_SCORE——和系统内部用的是同一个阈值。评测用被评测的机制定义「正确答案」，是闭环自证，永远发现不了上面那个缺口。5 道 reject 全是天气这类「检索分低」的题，没有一道是「点名库外法规」或「不可判定问题」。
- 15:07 15:40【设计原则】确定性优先：凡是「答错了会严重误导用户」的行为（编造库外法规条文、替用户做适用性判定、把笼统问题当成已知情况回答），一律由服务端代码拍板，不交给 7B 模型。好处不只是更稳，还在于这些保证可以离线验证——不启动 Ollama 也能跑测试证明它们成立。
- 15:07 15:40【教训】修一个方向的错，必须检查反方向有没有开出新口子。规则2 原本为了修「检索到了却说找不到」而写成「绝对不许说知识库未找到」，结果把「用户问的是库里根本没有的东西」这种真正该拒答的情形也封死了，直接导致编造法律条文。已把这条教训写进 docs/05 与 prompt.py 的 docstring。
- 15:07 15:40【教训】用被评测的机制去定义「正确答案」是闭环自证，结构上不可能发现该类缺陷。旧的 reject 题判定用的是系统内部同一个阈值，所以「阈值过了但不该答」的问题长期不可见。现已改为按问题类型分层断言，且每类都卡最小样本数。
- 15:15 异常输出一律不许端给用户。坏掉的 JSON 只抢救 answer 一个字段，引用和风险标签统统由服务端按检索结果补齐；连正文都救不出来就干脆改成列出条款。宁可少给东西（哪怕退化成只列条款），也绝不能让用户看到半截花括号。已沉淀为 docs/00 的第六条规则
- 15:15 本条缺陷的两个根因都是「条件挂错了变量」：JSON 失败分支把 raw 原文当正文、引用兜底判据写成了「处于降级模式」而真正该判的是「没有可用引用」。教训：写兜底条件时要问一句「这个变量在这条路径上真的会变成我期待的值吗」，而不是「我以为它是什么」
- 15:41 踩坑：index.html 里静态写了一份空状态，chat.js 的 renderEmptyState() 又生成一份，两个 id=emptyState 同时显示，首页出现重复标题和两套快捷卡片。原来就有这个缺陷，只是旧样式把所有内容居中堆叠、看不出来；改成左对齐后就露出来了。修法是生成前先删掉已存在的那一份。
- 15:41 验证方式：Chrome headless 截图逐页比对。Chrome 在 Windows 上的最小窗口宽度约 500px，--window-size=390 拿到的仍是 504px 布局视口（截图会被裁掉，看着像溢出，其实是假象）；要看真实手机布局必须把页面放进 390px 宽的 iframe 里，媒体查询才按 390px 生效。后来改用 CDP 的 Emulation.setDeviceMetricsOverride，比 iframe 更直接
- 16:00 决策：字体自己托管在本机，不引 CDN、也不引 Google Fonts。理由是这个工具承诺「断网也要能用」，引在线字体会让断网时界面直接降级；两个 woff2 子集一共 123 KB，代价可接受
- 16:00 决策：浏览器自动化不用 puppeteer / playwright，改用 tools/cdp_eval.js 直接讲 CDP 协议。因为项目要求零运行时依赖且离线可用，测试基础设施不该成为例外（Node 自带 WebSocket 和 fetch 就够了）
- 16:00 决策：测试缺 Node / Chrome / axe 时**直接判失败并说明缺什么**，不静默跳过。静默跳过等于给自己发一张假的通行证，宁可红得吵一点
- 16:00 决策：没用 PYTHONUTF8=1 解决 GBK 崩溃，而是 app/console.py 只对 sys.stdout / sys.stderr 做 reconfigure。因为 PYTHONUTF8=1 会连带改掉 open() 的默认编码，影响面更大，为一个打印问题不值当
- 16:00 决策：axe 报的 color-contrast「incomplete」不当缺陷修。实测被标节点的中心点全在视口外（.session-item:nth-child(20) > .title 的 rect.top=842、innerHeight=848；#pager > span 的 rect.top=5124），axe 拿不到背景色是几何裁剪造成的。测试里改为断言「每个 color-contrast 节点的中心点都在视口外或尺寸为 0」，出现视口内的才判失败——**不然以后有人会去"修"一个不存在的问题**
- 16:00 决策：axe 的 5 处违规里，`#sessionList` 和 `#kbTree` 的 scrollable-region-focusable 是被当成真问题修的（会话标题、删除、目录树节点全改成真按钮），不是为了让扫描变绿。原来键盘用户聚焦不到这些元素，等于用不了这两个功能——**自动规则报出来的是症状，底下是真缺口**
- 16:00 教训：无障碍修复本身也会引入新违规。把 <h1> 放在 <body> 直接子元素下修掉了 page-has-heading-one，却触发了 axe 的 region 规则（内容不在任何地标区域内），必须放进 <main>。修完要重扫，"变绿了"和"还是绿的"是两件事
- 16:00 坑：tests/test_frontend.py 第一版 12/17，会话列表相关三条全挂。根因是用 uvicorn 的 lifespan="off" 起测试服务，STARTUP_STATE 永远停在 ready=False，而 chat.js 的 init() 是先 await pollStartup()、ready 之后才加载会话列表和健康状态——于是页面一直盖在启动遮罩上。修法是启动测试服务时显式把 STARTUP_STATE 置为 ready
- 16:00 坑：Python 假值陷阱。断言 if (d.get("left") or -999) < -1，抽屉正常打开时 left 就是 0，被当成假值取了 -999，于是误报「抽屉没打开」。改成显式判断 is None。教训：只要数值 0 是合法结果，就不能用 or 兜底
